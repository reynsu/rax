## Reflection: defense-in-depth pattern that emerged

Three of the round-2 HIGHs (R2-H1, R2-H2, R2-M1) follow a single shape: **a previous "validate the input charset" mitigation passed the regex but missed a structural attack at a higher abstraction level**. Charset isn't enough when the attacker can replay the delimiter, embed text in a different paragraph, or chain `..` past a regex that doesn't model path semantics. The fixes layer **structural** validation on top of the charset checks (nonce-based delimiters, paragraph boundaries, explicit `..`/blocklist gates).

For LLM-pipeline tools specifically, this is going to keep happening. **Charset filtering is necessary but never sufficient** when the downstream consumer is parsing structure, especially when the structure is "natural language fed to an LLM". Future review rounds should assume that any new flag flowing into the prompt requires both a charset filter AND a structural envelope.
